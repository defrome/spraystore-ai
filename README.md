# spraystore-ai

## Каталог товаров из Яндекс KIT

Нейронка может рекомендовать реальные товары магазина и называть актуальные цены и наличие.
Интеграция **только на чтение**: используются одни GET-запросы (в `service/kit_client.py` нет методов для других
глаголов). Заказы, клиенты, платёжные ссылки, вебхуки и вложения не трогаются.

**Включение**
1. В KIT: Настройки → API → «Сгенерировать токен» (показывается один раз; токен даёт полный доступ — храните только на бэкенде).
2. Положите его в `service/.env`: `KIT_API_TOKEN=...` (пример — `service/.env.example`). `.env` в git не попадает.
3. Первая синхронизация: `python service/catalog.py --sync`. Дальше сервис сам обновляет индекс в фоне (при старте и раз в час).
4. Посмотреть индекс: `python service/catalog.py --stats` и `python service/catalog.py --show "краскопульт для лака" --max-price 10000`;
   состояние также в `GET /api/health` (поле `catalog`).

Без токена каталог выключен, чат работает как раньше. Сбой синхронизации не роняет сервис — остаётся прошлый индекс.

**Как это работает.** Товары (`GET /v1/variants`, статус PUBLISHED + категории, характеристики, картинки) индексируются в отдельной
коллекции Chroma `products`. Перед ответом цена и наличие уточняются точечно через `GET /v1/variants/{id}` (кэш на пару минут);
если KIT недоступен, берутся данные индекса с пометкой «актуальность не проверена». Лимит KIT (3 запроса/сек) соблюдается троттлингом.
В ответе `/api/chat` появляется поле `cards` (`{id, name, price, url, image?, in_stock}`) — только для товаров, названных в ответе.

**Переменные окружения**
- `KIT_API_TOKEN` — токен KIT (пусто — каталог выключен).
- `CATALOG_MODE` — `context` (по умолчанию: товары ищутся заранее и кладутся в контекст), `tools` (модель сама вызывает
  `search_products` через function calling), `auto` (пробуем tools, при ошибке API откат на context).
- `CATALOG_SYNC_INTERVAL_MIN` — период фоновой синхронизации, по умолчанию 60.
- `CATALOG_LIVE_TTL_SEC` — кэш живых цен/наличия, по умолчанию 180.
- Дополнительно: `CATALOG_MIN_SCORE` (порог релевантности поиска, 0.70), `CATALOG_STORE_URL` (домен витрины для ссылок,
  по умолчанию `b2c_url` магазина из KIT), `CHROMA_PATH` (путь к Chroma для товаров).

**Тесты** (без сети и токена): `pip install pytest && python -m pytest service/tests`.

Следующие шаги (вне текущей версии): документы-вложения (`/v1/variants/{id}/attachments`) в RAG, похожие товары
(`/v1/products/cards/{id}/similar`).

## Админка (`/admin`)

Страница для того, чтобы «обучать» бота без правок кода: разбирать плохие ответы, править базу знаний и проверять результат.

1. В `service/.env` задайте `ADMIN_TOKEN=<длинная случайная строка>` (например, `openssl rand -hex 24`). Пока токен не задан, админка выключена.
2. Запустите сервис и откройте `http://localhost:8000/admin`, введите токен.

Разделы:
- **Входящие** — дизлайки, жалобы и вопросы, на которые бот не нашёл ответ. «Исправить ответ» сохраняет пару «вопрос — ответ» в базу (она получает приоритет над статьями) и по желанию добавляет её в контрольный набор. Клавиши: `J`/`K` — листать, `E` — исправить.
- **База знаний** — статьи и пары «вопрос — ответ». Хранятся в SQLite (`service/chat_log.db`), при первом запуске туда загружается встроенная база из `main.py`. Любое сохранение сразу обновляет поисковый индекс. Есть история версий; удаление можно отменить.
- **Песочница** — что бот находит по вопросу (фрагменты, оценки, порог уверенности), полный промпт и, по кнопке, ответ модели.
- **Проверки** — контрольные вопросы: должен найтись нужный материал и/или ответ должен содержать нужные факты. Проверка фактов вызывает модель, поэтому включается отдельной галочкой.
- **Статистика** — вопросы, лайки/дизлайки, оценка диалога, частые вопросы без ответа, причины дизлайков.

Доступ — по Bearer-токену (после 10 неверных попыток с одного адреса — пауза на 5 минут). Админку не стоит выставлять наружу без HTTPS.

## Деплой на стейджинг (Docker)

Стейджинг: `http://158.160.204.91/` (чат), `/admin` (админка), `/embed-example.html` (пример встраивания).
Состав: `Dockerfile` (приложение, модель эмбеддингов запечена в образ), `docker-compose.yml` (приложение + nginx на порту 80),
`deploy/nginx.conf` (прокси, лимиты запросов на чат и админку), `deploy/deploy.sh`.

На сервере (нужны Docker + compose plugin, открытый порт 80):
```bash
git clone https://github.com/defrome/spraystore-ai && cd spraystore-ai
cp service/.env.example service/.env      # заполнить GENAPI_KEY, ADMIN_TOKEN (openssl rand -hex 24), KIT_API_TOKEN по желанию
./deploy/deploy.sh                        # сборка, запуск, ожидание /api/health
```
Обновление: `git pull && ./deploy/deploy.sh`. Логи: `docker compose logs -f app`.

- Данные (SQLite с диалогами и базой знаний, индекс Chroma) лежат в томе `data` и переживают пересборку.
  Бэкап: `docker compose cp app:/data ./backup`.
- Наружу публикуется только nginx; приложение доступно лишь внутри docker-сети. `service/.env` в образ не копируется, а подставляется при запуске.
- `CORS_ORIGINS` по умолчанию `http://158.160.204.91`; чтобы встраивать чат с другого домена, задайте его в окружении перед запуском.
- **HTTPS нет**: токен админки и вопросы пользователей идут открытым текстом. Для стейджинга с тестовыми данными допустимо;
  перед боевым запуском нужен домен и сертификат (certbot или Caddy перед nginx).
- Один воркер uvicorn — намеренно (SQLite и Chroma не рассчитаны на несколько процессов).
